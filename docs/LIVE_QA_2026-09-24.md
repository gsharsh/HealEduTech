## Defects addressed in this QA change

- Guest “Continue browsing” returned to a sign-in prompt instead of public browsing.
- Email callback URLs discarded the selected book destination; safe local destinations now travel with callbacks.
- Entering sign-in from a scrolled book page retained scroll position; the page now starts at the top with main-content focus.
- Search/topic/page state disappeared after opening a book and returning; state now lives in validated URLs and detail return links.
- Accent-free Vietnamese queries missed accented titles. A security-invoker search RPC uses accent normalization and literal substring matching, with bounded input.
- Unknown copy totals were displayed as zero; details now distinguish unknown from confirmed zero.
- Malformed book IDs produced a retry error; they now produce not-found.
- A 320-pixel viewport with a vertical scrollbar overflowed horizontally due to the body's minimum width; the fixed login/catalogue views fit the available 305 CSS pixels.
- The Peter Rabbit sample image was a calendar cover. A guarded data correction clears only that known incorrect URL, restoring title artwork.

## Still requires real-account or operational validation

- Successful email/password login, email delivery, signup verification, magic-link completion, password reset completion, session renewal, sign-out, and saved reading/interests persistence were not exercised with a real test account. A user-operated test-account login was requested; no password should be sent in chat.
- Cross-account live RLS testing and staff lending mutations need dedicated disposable accounts/fixtures. No real loan or learner data was changed for QA.
- Circulation is intentionally not released. Do not enable lending to satisfy a test.
- Supabase reports compromised-password protection disabled. Review the project's Auth settings and plan support before enabling it.
- The `book_availability` security-definer view is deliberate: guests see book IDs and aggregate counts only. The advisor warning remains; changing it blindly to invoker would break public availability under inventory RLS.
- The bootstrap table's no-policy notice is deliberate: it has no guest/learner grants.
- Database audit found live `correct_copy_condition` RPC drift/default public EXECUTE and broader authenticated circulation table grants than needed. Staff checks and RLS still block unauthorized operations; reconcile these in a dedicated hardening migration.
- Nine foreign-key index notices and one unused-index notice remain informational; do not remove a lending index merely because the disabled pilot has not used it.
- Deployment audit: SPA routes and sampled eager/lazy assets return 200, HTML revalidates, and HSTS is present. CSP, frame protection, content-type sniffing prevention, referrer policy and permissions policy were absent from sampled HTML responses; add and test these as a separate hosting-hardening change.
- This is sampled desktop/mobile and keyboard verification, not a complete accessibility certification or representative student usability study.
